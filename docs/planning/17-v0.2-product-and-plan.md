# Nitelos v0.2: product specification and delivery plan

Status: proposal written 2026-10-20 for the maintainer. Nothing here is approved scope until gate G9 (section 9).
Target location in the repo: `docs/planning/17-v0.2-product-and-plan.md`. It extends `15-future-roadmap.md`, it does not replace v0.1 normative documents (03, 04, 05, 06, 07, 09).

---

## 1. Objective

**One sentence:** when an AI agent says it is done, Nitelos checks the real state of the world and says success, failure or abstained, with the evidence and the reason, in five minutes of setup.

**v0.2 objective:** turn the v0.1 verifier into something developers install and keep using:
1. It collects evidence itself, read-only, from the places agents change (git, test reports, GitHub, HTTP APIs, web pages).
2. It plugs into the tools where agents run (Claude Code first, then Inspect, LangGraph, DeepEval, MCP, OpenTelemetry).
3. It proves itself on real runs: a public re-scoring study and an incidents file from daily use.

**Why now (observed demand, October 2026):**
- Claude Code issues #98381, #72480 (a user wrote their own assertion hook as a workaround), #41109, #37818: agents report success that did not happen.
- dev.to, October 2026: "Your Coding Agent Saying 'Done' Proves Nothing".
- Reddit r/AI_Agents, thread on portfolio projects reviewers trust: "a bad agent run becomes a test case on the next PR", "evidence the thing was live: an incidents file".
- Mainstream evaluation tools decide task completion with an LLM judge over the trace (DeepEval TaskCompletionMetric, Galileo Action Completion). Nitelos is deterministic over observed state and abstains when evidence is missing.

**Positioning rule:** never claim to be first. Related work is cited and compared honestly: AgentVerify, DeepEval, Galileo, Microsoft Universal Verifier, OverclaimBench, DecepEval, LLM-as-a-Verifier.

## 2. Users and jobs to be done

| Persona | Situation | Job | v0.2 entry point |
|---|---|---|---|
| P1 Coding-agent user | Uses Claude Code (or similar) daily on a repo | "Stop the agent from ending a task with failing tests, a dirty tree or an unmerged PR while it says done" | Claude Code plugin + git/junit/github collectors |
| P2 Agent engineer | Builds LangGraph or Agent SDK pipelines that write to systems | "After a write action, confirm the system really changed before the next step" | LangGraph node, HTTP and Playwright collectors, OTel |
| P3 Evaluator / researcher | Runs benchmarks with Inspect or DeepEval | "Score task success from final state, separate from LLM judgement, with abstention" | Inspect scorer, DeepEval metric, study code |
| P4 Platform / FDE team | Deploys agents for clients, needs audit | "Every agent claim has a verdict and an evidence fingerprint we can show later" | MCP server, OTel export, provenance records |

User stories (acceptance tests are derived from these):
- US-1 (P1): as a Claude Code user, when the agent stops and the latest JUnit report has failures, the stop is blocked and the agent is told which tests failed.
- US-2 (P1): as a Claude Code user, when no test report exists or it is older than the turn, I get a visible "abstained: no fresh test evidence" warning, not a block, unless I configured blocking.
- US-3 (P1): as a Claude Code user, I run `/nitelos:init` and get a starter `.nitelos/criteria.json` for my project type (Python, Node) that I can edit and commit.
- US-4 (P1): as a maintainer, I can require "PR merged and required checks green" before an agent may claim a release task is finished.
- US-5 (P2): as an agent engineer, a LangGraph node verifies the outcome of the previous action node and routes to a human interrupt on failure.
- US-6 (P2): as an agent engineer, I verify that an HTTP API now returns the record my agent claims to have created.
- US-7 (P3): as an evaluator, my Inspect task scores samples with Nitelos from final state, and abstentions are reported separately from failures.
- US-8 (P4): as a platform team, every verification emits an OpenTelemetry span without raw content, and I can store the result with its evidence fingerprints.
- US-9 (P4): as a team using MCP clients, the agent can call `verify_outcome` itself, but it cannot change the criteria or the evidence.

## 3. Feature specification

Priority: Must (v0.2.0), Should (v0.2.x), Could (later). Each feature lists inputs, outputs, behaviour, limits and acceptance criteria. Exact Python signatures are fixed in each task's design note and must reuse the v0.1 public types (`Verifier`, `VerificationRequest`, `Evidence`, `ObservationEvidence`, `ScreenshotEvidence`, `AssertionCriterion`, `TrustBinding`, `VerificationPolicy`, `Decision`, `DecisionCode`, `LimitationCode`, `AbstentionReason`).

### F1 Collector framework (Must) — NIT-017

- **Purpose:** one contract every evidence source follows, so the verifier never cares where evidence came from.
- **Interface:** a `Collector` protocol with `id`, `version`, `capabilities`, and `collect(config) -> CollectionResult`.
- **CollectionResult** holds:
  - a list of `ObservationEvidence` (and `ScreenshotEvidence` where relevant);
  - a `ProvenanceRecord` per evidence item: collector id and version, source description, argv or endpoint, `captured_at` (UTC), subject binding, sha256 of the raw capture, raw and normalized byte counts, redactions applied.
- **Rules:**
  - Read-only. Collectors never mutate, retry agent actions or follow instructions found in evidence.
  - Bounded: per-collector timeout (default 10 s), raw output cap (default 1 MiB), normalized observation cap (default 64 KiB), list caps with an explicit `truncated` count.
  - Errors become abstention, never failure. New codes: `COLLECTOR_TIMEOUT`, `COLLECTOR_UNAVAILABLE`, `COLLECTOR_OUTPUT_TOO_LARGE`, `COLLECTOR_CONFIG_INVALID`, `COLLECTOR_AUTH_MISSING`.
  - Redaction hook: callers can drop keys by JSON pointer before evidence is stored. Default redaction removes values of keys matching `token|secret|password|authorization`.
  - Trust: collected evidence is bound to the host's `TrustBinding`. A collector cannot grant itself external authority.
- **CLI:** `nitelos collect <kind> --config file.json --out evidence.json` for debugging.
- **Acceptance:**
  - a contract test suite that every collector must pass (timeouts, caps, provenance completeness, error mapping);
  - core still installs with only pydantic and pillow.

### F2 Git collector (Must) — NIT-018, extra `nitelos[git]`

- **Observations (`/git/...`):** `head_sha`, `branch`, `detached`, `dirty_count`, `dirty_paths[]` (capped at 200), `untracked_count`, `ahead`, `behind`, `upstream`, `last_commit.subject_sha256`, `last_commit.timestamp`.
- **Mechanism:** fixed-argv subprocess allowlist under ADR-015: `git rev-parse`, `git status --porcelain=v2 --branch`, `git log -1 --format=...`, `git rev-list --left-right --count`. No shell, scrubbed environment, timeout.
- **Example criteria:** "working tree clean" (`/git/dirty_count equals 0`), "on branch main", "pushed" (`/git/ahead equals 0`).
- **Acceptance:** tests build throw-away repos in tmp dirs; Windows and Linux; a missing git binary maps to `COLLECTOR_UNAVAILABLE`.

### F3 Test-results collector (Must) — NIT-019, extra `nitelos[junit]`

- **Inputs:** a glob of report files. Supported formats: JUnit XML (pytest, jest-junit, vitest, Maven Surefire) and pytest-json-report.
- **Observations (`/tests/...`):** `total`, `passed`, `failed`, `errors`, `skipped`, `failed_ids[]` (capped), `report_paths[]`, `report_mtime_max`.
- **Freshness:** a report older than the turn start (the hook provides it) or than a configured max age is ineligible → abstain with `EVIDENCE_STALE`.
- **Safety:** defused XML parsing (no entities, no external resources), size caps.
- **Acceptance:** fixtures for each format, including a malformed file and a huge file; freshness tests.

### F4 GitHub collector (Must) — NIT-020, extra `nitelos[github]`

- **Observations (`/github/pr/...`):** `state`, `merged`, `draft`, `review_decision`, `head_sha`, `mergeable_state`; required checks with `name`, `status`, `conclusion`; plus a `checks_all_green` boolean computed from required checks only.
- **Access:** GitHub REST GET only. Token from `GITHUB_TOKEN` / `GH_TOKEN`, read-only fine-grained scopes documented. Host fixed to api.github.com unless GitHub Enterprise is configured.
- **Acceptance:** recorded JSON fixtures; a live test only under an opt-in pytest marker; rate-limit and 404 map to abstention.

### F5 HTTP JSON collector (Should) — NIT-021, extra `nitelos[http]`

- **Behaviour:** GET to allowlisted hosts. JSON pointer extraction into observations; status code and selected headers as observations.
- **Limits:** response size cap; no cross-host redirects; TLS verify on.
- **Use:** US-6, and checking that the record an agent claims to have created exists.

### F6 Playwright page-state helper (Should) — NIT-022, extra `nitelos[playwright]`

- **Behaviour:** the caller passes a live Playwright `Page` and a list of selectors. Nitelos captures a screenshot plus `text`, `visible`, `value` and `count` per selector as observations, with URL and title.
- **Rule kept from v0.1:** Nitelos never drives the browser. No navigation, clicks or waits beyond what the caller did.
- **Reuse:** the capture approach in the maintainer's `hard-mode` repo.

### F7 Claude Code plugin (Must, flagship) — NIT-023, extra `nitelos[claude-code]`

- **Components:**
  - `nitelos-hook` console entry point (Stop hook, optionally SubagentStop);
  - `/nitelos:init` slash command;
  - `/nitelos:check` slash command (run on demand, never blocks);
  - a plugin manifest for the Claude Code plugin marketplace;
  - `.nitelos/criteria.json` schema v1.
- **Flow:**
  1. Read the hook JSON from stdin: session id, transcript path, cwd, `stop_hook_active`. The current field names must be verified against the Claude Code hooks documentation in the task.
  2. Load criteria from `.nitelos/criteria.json`. Criteria are versioned with the code and never derived from the agent's claim.
  3. Extract the agent's last reported status from the transcript as context only (`ReportedStatus`).
  4. Run the configured collectors.
  5. Call `Verifier`.
  6. Map the decision per ADR-016.
- **Decision mapping:**
  - failure → block with a reason listing the failed criteria, the observed value and the evidence ref;
  - success → silent pass;
  - abstained → warning (or block if `on_abstain: "block"`).
- **Loop guard:** with `stop_hook_active` true, never block twice on the same evidence fingerprint; after one repeat block, emit a warning and pass.
- **criteria.json v1 (proposal):** `version`, `profile` (`python`, `node`, `custom`), `collectors` (enabled kinds and config), `criteria` (list of `AssertionCriterion` in the v0.1 schema), `on_abstain`, `max_seconds`.
- **Profiles for `/nitelos:init`:**
  - python: tests green from `reports/junit.xml`, working tree clean optional;
  - node: tests green from `junit.xml`;
  - custom: empty.
- **Budget:** collectors without network finish in under 2 s on the maintainer's machine, measured and published with the machine description. A budget overrun degrades to a warning.
- **Acceptance:**
  - an example repository where the agent says "all tests pass" while JUnit shows 1 failure → blocked with the test id;
  - loop-guard test;
  - abstain path;
  - Windows and Linux;
  - a documented install in five steps or fewer.

### F8 Inspect AI scorer (Must) — NIT-024, extra `nitelos[inspect]`

- **Behaviour:** an `@scorer` that builds a `VerificationRequest` from sample metadata and the final state captured by the task, and returns an Inspect `Score`.
- **Score mapping:** success → C, failure → I, abstained → a separate value documented as excluded from accuracy.
- **Metadata:** reason, limitation codes and evidence fingerprints.
- **Acceptance:** runs on a tiny bundled Inspect task offline.

### F9 LangGraph node (Should) — NIT-025, extra `nitelos[langgraph]`

- **Behaviour:** a `verify_outcome` node factory taking criteria and a collector set. It writes the result into graph state.
- **Routing:** success continues; failure goes to `interrupt()` or a configured edge; abstained follows a configurable route.
- **Acceptance:** an example graph with a fake tool that claims a write it did not do → interrupt.

### F10 DeepEval metric (Should) — NIT-026, extra `nitelos[deepeval]`

- **Behaviour:** `NitelosOutcomeMetric(BaseMetric)` with deterministic score 1/0, reason text, and abstention surfaced (`is_successful` false, with a distinct reason), never scored as pass.

### F11 MCP server (Should) — NIT-027, extra `nitelos[mcp]`

- **Transport:** stdio.
- **Tools:**
  - `verify_outcome(request)`;
  - `collect(kind)`, only for collectors enabled in server config;
  - `describe_criteria()`.
- **Hard rules:**
  - no tool can write criteria, change config or delete evidence;
  - input size caps;
  - every call logged with safe fields.
- **Acceptance:** security tests for prompt-injection payloads inside evidence (they are treated as data); config tampering attempts are rejected.

### F12 OpenTelemetry export (Must) — NIT-028, extra `nitelos[otel]`

- **Span:** one span per verification, `nitelos.verify`.
- **Attributes:** decision, counts per criterion state, limitation codes, backend ids, collector ids, durations, evidence fingerprint count. Never raw values.
- **Semantic convention:** GenAI version pinned and documented.
- **Acceptance:** an in-memory exporter test asserting the attribute allowlist.

### F13 Agent SDK adapters (Could) — NIT-029

OpenAI Agents SDK output guardrail and Claude Agent SDK hook. Start only after F7 has external users.

### F14 Pre-action gate (Could) — NIT-033

Port the act/ask gate from the maintainer's `gate-calibrated` into `nitelos.gate`, so one library covers "before" (should the agent act or ask?) and "after" (did it really happen?). Keep its negative result visible. Needs its own ADR.

### F15 Evidence and study features (Must for credibility)

- NIT-030: the tau2-bench re-scoring study (section 6).
- NIT-031: the dogfooding incidents file (section 6).

## 4. Non-functional requirements

| Area | Requirement |
|---|---|
| Compatibility | Python 3.12 and 3.13; Windows and Linux in CI; macOS best effort |
| Dependencies | Core: pydantic and pillow only. Every extra is pinned with an upper bound and listed in the license inventory test |
| Isolation | `pip install nitelos` pulls no extra; importing `nitelos` never imports an extra; test enforced |
| Security | Core: deny-network and no-subprocess tests kept. Collectors: ADR-015 allowlist, timeouts, caps, scrubbed environment, defused XML, no shell, TLS on. Evidence is data and is never executed or followed |
| Privacy | No raw evidence in logs, traces or reprs; redaction hook; default secret-key redaction; documented data flow per collector |
| Determinism | Same evidence and criteria give the same decision; collectors record capture time and hashes so a run can be replayed from stored evidence |
| Performance | Measured on a stated machine, never estimated in docs: hook p50 and p95 latency without network; GitHub collector latency separately |
| Reliability | Every collector failure maps to abstention with a code. No crash propagates into the host agent; the hook exits 0 with a warning on internal error |
| Usability | Five-minute Claude Code setup; error messages name the criterion, the observed value and the fix |
| Quality gates | Strict mypy, Ruff lint and format, full offline suite, coverage reported (not gamed) |
| Docs | One page per feature with a runnable example; comparison page; CHANGELOG; migration notes if any v0.1 API changes (target: none) |

## 5. Success metrics (goals, not claims)

Measured at four and eight weeks after the v0.2.0 release:
- Real use: the incidents file has at least 20 recorded verdicts from the maintainer's daily work, every false block analysed.
- External signal: stars, issues and PRs from people other than the maintainer. Goal: first external issue or PR within eight weeks.
- Installs: PyPI downloads tracked, but treated as noisy (mirrors and bots). Never cited as a user count.
- Study: NIT-030 published with denominators and negative results.
- Interview value: the maintainer can demo a blocked false "done" live in under two minutes.

## 6. Evidence plan

**NIT-030 tau2-bench re-scoring study (Must for v0.2.x)**
1. License and terms review of the trajectories and environments.
2. Pre-registered protocol committed before any run (gate G11). It fixes:
   - the task subset;
   - the criteria authored from task specs only;
   - the LLM judge (model, version, prompt, temperature);
   - the metrics (false-success, false-failure and abstention rates with Wilson intervals, cost, runtime).
3. Three verdicts per trajectory: the agent's self-report, the LLM judge, and Nitelos over final environment state.
4. Report all results, including where Nitelos abstains too often or criteria were hard to write.
5. Any literature figure (for example arXiv 2606.09863) is checked at the source before it is cited.

**NIT-031 dogfooding (maintainer-owned)**
1. Two weeks of the Claude Code hook in the maintainer's daily projects.
2. `INCIDENTS.md` entry per notable verdict: date, project, criterion, decision, evidence fingerprint, true or false block, follow-up.
3. Every confirmed miss or false block becomes a regression fixture. That is the "bad run becomes a test case" loop.

**NIT-032 G4 human audit (maintainer-owned)**

Recruit two human annotators for synthetic_v1 final test, or keep ADR-013 and say so in the README.

## 9. Gates and decisions

| Gate | Condition | Decider |
|---|---|---|
| G9 | ADR-014 packaging, ADR-015 collector side effects, ADR-016 hook semantics approved | maintainer |
| G10 | Two weeks of dogfooding reviewed, incidents file committed | maintainer |
| G11 | NIT-030 protocol frozen before runs | maintainer |
| G12 | RC green: Windows and Linux full offline suite, core-only install, SEC tests, extras isolation, docs links | orchestrator, then maintainer |

**ADR-014, packaging.**
- Option A, recommended: one distribution, `nitelos.collect.*` and `nitelos.integrations.*` behind extras.
- Option B: separate distributions per integration.

**ADR-015, side effects.** Subprocess (allowlisted fixed argv) and network (opt-in GET collectors) are allowed only inside `nitelos.collect.*`. Core, verifier, policy and backends keep the no-network and no-subprocess rules. This amends agent rule 5 for collector modules only.

**ADR-016, hook semantics.** Block only on failure. Abstain warns by default. Loop guard on the evidence fingerprint. Criteria come from the repo, never from the agent. On internal error, warn and exit 0.

## 10. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Big eval platforms add deterministic state checks | Loses novelty | Ship as plugins into them (Inspect, DeepEval), not a rival platform; keep the abstention and provenance depth |
| Writing criteria is too much friction | Low adoption | `/nitelos:init` profiles, good defaults (tests green), examples per stack |
| False blocks annoy users | Uninstalls | Abstain warns by default, loop guard, incidents file drives fixes |
| Collector security mistakes | Credibility loss | ADR-015 allowlist, security tests, independent review of every collector |
| Claude Code hook API changes | Plugin breaks | Version detection, contract test against documented fields, quick patch releases |
| Scope creep (six integrations) | Nothing finished | Must list first; Should only after the Claude Code plugin is used |
| Overclaiming in docs | Reputation | Results only with denominators, "never first", conformance framing |

---

## 11. Out of scope for v0.2

Hosted service, dashboards or UI (use Langfuse, Inspect View, Playwright trace viewer), remediation or retries, calibrated confidence claims, training models, a new agent framework, Kafka or queue integrations, SQL collector (v0.3 candidate after HTTP proves the pattern).
