Research accessed 2026-10-14. Primary documentation, repository contents, public GitHub metadata, model cards, and papers were inspected. No repositories were cloned or executed. Features below are documented capabilities, not independently reproduced performance. “Not established” means the reviewed material did not substantiate the feature; it does not prove absence. ## Direct overlap

### Microsoft Universal Verifier / Fara webeval

Facts: [repository](https://github.com/microsoft/fara), [trajectory and verifier documentation](https://github.com/microsoft/fara/blob/main/webeval/README.md), [paper](https://arxiv.org/abs/2604.06240). Python; MIT repository license. The verifier consumes goals, screenshots, actions, and final answers; rubric and outcome judgments are separate. Standalone trajectory rescoring exists, with multimodal judge configuration and ambiguity diagnostics. CUAVerifierBench supplies human labels. Calibration of its scores as completion probabilities is not established. Latest observed substantive repository update: 2026-07-22, Fara1.5 release (`a675d6d`). Interpretation: strongest functional overlap; reuse a later adapter rather than reproduce its rubric/context machinery. It is a larger evaluation/agent ecosystem than the proposed SDK; no claim that it requires using Fara as the acting agent.

### AgentHorizon

Facts: [repository and documentation](https://github.com/ServiceNow/agenthorizon), [dataset](https://huggingface.co/datasets/ServiceNow/AgentHorizon), [protocol](https://github.com/ServiceNow/agenthorizon/blob/main/docs/evaluation-protocol.md). Python harness for screenshot/action trajectory completion judges; 1,373 trajectories, including instruction-swapped negatives. Extensible through a judge's structured verdict files; Claude/Gemini CLI paths are documented. It reports correctness and mistake categories; calibrated abstention is not established. Observed 2026-10-06 documentation merge (`8584a34`); very recent research, maintenance longevity unknown. Neither inspected repository root nor dataset card established an applicable redistribution license. Interpretation: direct benchmark overlap; useful future evaluation source after permission. Its long trajectories exceed Nitelos's v0.1 limits. Do not silently call a two-frame subset an AgentHorizon reproduction.

### AgentVerify

Facts: [repository](https://github.com/aliasfoxkde/AgentVerify), [docs](https://github.com/aliasfoxkde/AgentVerify/tree/main/docs). Rust, MIT; 2026-10-11 test fix (`f55e171`). Deterministic postconditions over external observations, REST/Postgres/Redis observers, unknown outcomes, receipts and signing support, and execution/retry machinery are documented. It does not require a model; observer/contract interfaces provide extension. No calibrated visual prediction method is established. Evaluation evidence inspected is engineering tests, not a cross-domain GUI judge benchmark. Interpretation: explicit external verification and provenance are not novel. Do not rebuild its observer/recovery infrastructure. A later receipt importer is plausible; maturity and security properties have not been independently audited.

### LLM-as-a-Verifier

Facts: [repository/docs](https://github.com/llm-as-a-verifier/llm-as-a-verifier), MIT, Python; observed 2026-10-08 release 0.3.0 (`90e8fc2`). Provides trajectory comparison, selection, and progress tracking with criteria and generative verifier models; documented DeepSeek/Vertex and compatible endpoint configuration. Benchmarks span multiple agent domains. Project claims support across modalities, but exact image transport compatibility requires adapter-level inspection before integration. Explicit calibrated outcome probabilities and externally trusted state semantics are not established. Interpretation: major overlap in framework-independent verification; comparative rewards are not automatically calibrated binary task probabilities. Consider wrapping its output as a model judgment, preserving the original score meaning; do not copy its whole selection/training stack.

## Model and statistical sources

- [SmolVLM-500M-Instruct card](https://huggingface.co/HuggingFaceTB/SmolVLM-500M-Instruct): Apache-2.0 checkpoint; image/text input and text output; documented processor plus Vision2Seq generation. HF API revision `a7da5b986cb59b408707209984f360a5f4ad7e47`, modified 2025-04-08. [Transformers SmolVLM documentation](https://huggingface.co/docs/transformers/model_doc/smolvlm) is the library-interface reference. Select for modest footprint and permissive release, not demonstrated GUI accuracy. Card memory claims are not a Nitelos measurement.
- [Qwen2.5-VL-3B card](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct): credible alternative with a distinct processor/model path. Weight-license compatibility was not resolved in this inspection; no inclusion or redistribution recommended. Larger models increase release hardware burden; do not silently replace the chosen baseline.
- [Guo et al. 2017](https://proceedings.mlr.press/v70/guo17a.html): temperature scaling of classifier logits is a calibration technique, not proof that verbal LLM confidence is calibrated.
- [El-Yaniv and Wiener 2010](https://www.jmlr.org/papers/v11/el-yaniv10a.html): selective classification motivates reporting risk together with coverage. Its assumptions do not automatically transfer to arbitrary GUI domains.
- [SciPy binomial inference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html): reuse numerical statistical routines in the evaluation extra; no bespoke statistical library.

## Data access and licensing disposition

[CUAVerifierBench](https://huggingface.co/datasets/microsoft/CUAVerifierBench) is the best inspected real-world starting point: card declares MIT and includes screenshots/actions plus human annotations, including blind/informed conditions. Use blind annotations for primary evaluation and keep ambiguous labels separate. It includes trajectories produced on real sites; the card license does not settle third-party screenshot/privacy rights. Prefer separately obtained data and local-only evaluation. AgentHorizon is relevant but permission unresolved. BrowserGym trace exports and OSWorld/WebArena state evaluators are alternatives, each with asset-specific audits. No third-party dataset or screenshot is bundled in v0.1.

At inspection, [PyPI JSON for nitelos](https://pypi.org/pypi/nitelos/json) and [proposed public GitHub repository API](https://api.github.com/repos/Gjusev/nitelos) returned HTTP 404. This does not reserve the package name, establish publish rights, exclude a private repository, or provide trademark clearance. Recheck at release.

License review is a dependency gate, not a blanket legal clearance. Apache's [third-party license policy](https://www.apache.org/legal/resolved.html) is useful guidance; retain the actual notices and inspect exact distributed wheels/assets. [Technology decisions](08-technology-decisions.md) lists material dependencies. No external code or dataset has been copied into this plan.

## Novelty assessment and integration decision

No individual proposed differentiator is established as novel. A useful gap may remain in a compact Python SDK with conservative evidence scopes and error-aware reporting, independent of agent execution and large research harnesses. This must be tested with users. Existing systems could implement similar contracts with custom scorers. If adoption feedback shows that an Inspect scorer or Universal Verifier adapter fully solves the intended use case, prioritize that integration and shrink Nitelos further. Do not claim a new verifier algorithm, formal proof of authenticity, or state-of-the-art performance.

Research limitations: API metadata and documentation were inspected, not execution quality or full security histories. License ambiguity is preserved rather than guessed. The Microsoft subdirectory web fetch failed; its raw README was retrieved successfully. An initial selective-classification paper URL failed; the linked JMLR primary source replaced it. All dates and interfaces require revalidation before implementation dependency locking.
